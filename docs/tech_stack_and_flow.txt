2. THE FIVE KEY INGENIOUS FACTORS OF SMART CAMPUS AI
================================================================================

FACTOR 1: MULTI-DIMENSIONAL PERSONA RELEVANCE FORMULA (0% TO 100%)
--------------------------------------------------------------------------------
Implemented in `src/lib/relevance.ts`, prevents notice spam by scoring every
circular specifically against the logged-in student:
  - Base Score: +50% (Standard university notice baseline).
  - Department / Branch Alignment:
    * Exact Match (e.g. Student is CSE, Notice targets CSE/IT): +25%
    * Direct Mismatch (e.g. Student is CSE, Notice is strictly MECH): -35% penalty
  - Academic Year Alignment:
    * Exact Year Match (e.g. 3rd Year notice for 3rd Year student): +20%
    * Cross-Year Penalty (e.g. 1st Year notice for 4th Year student): -25% penalty
  - Career & Academic Interests:
    * Keywords (e.g. "Hackathon", "TCS", "Robotics", "Scholarship"): Up to +16%
  - Career Placement Gatekeeper:
    * Placement/Internship drive automatically boosted for 3rd & 4th year students: +15%
  Final Output: Clamped between 0% and 100% with high-relevance badges (>=75%).

FACTOR 2: TIME-DECAY URGENCY CLASSIFICATION
--------------------------------------------------------------------------------
Tasks are prioritized dynamically based on distance to deadline:
  - CRITICAL (< 48 hours remaining, or exam penalty/fine mentioned): Red Badge (#D9402B)
  - HIGH     (2 to 5 days remaining, or placement/fee deadlines): Orange Badge (#FF5A1F)
  - MEDIUM   (5 to 14 days remaining, normal project/club deadlines): Amber Badge (#D97706)
  - LOW      (> 14 days remaining or open-ended informational circulars): Gray Badge (#6B7280)

FACTOR 3: ZERO-HALLUCINATION JSON SCHEMA EXTRACTION
--------------------------------------------------------------------------------
Instead of unconstrained natural language prompts, Groq is forced into strict
JSON Schema output mode (`response_format: { type: "json_object" }`). Every
notice is systematically deconstructed into:
  - Title, Category, Summary, ISO Deadline, Urgency, Eligibility, ActionSteps,
    TargetBranches, TargetYears.

FACTOR 4: GROUNDED RAG PROVENANCE & NOTICE CITATIONS
--------------------------------------------------------------------------------
When a student asks questions in Cmd+K Chat (e.g., "What is the fee deadline for CSE?"):
  1. Backend retrieves the verified ExtractedTasks and raw Notices for the active student.
  2. Groq synthesizes the response strictly constrained to that database context.
  3. Returns grounded text with interactive citation chips (`[Notice #12: Semester Fee Circular]`).

FACTOR 5: ZERO-DOWNTIME DETERMINISTIC REGEX FALLBACK ENGINE
--------------------------------------------------------------------------------
If external API rate limits, network outages, or key expirations occur:
  - System intercepts error in `src/lib/groq.ts`.
  - Automatically activates local Regex Heuristic Parser to extract deadlines,
    urgency, and bulleted action steps without crashing or losing data.

4. VERIFIED API CONTRACTS
================================================================================

1. GET/POST /api/profile
   - Fetch active student profile or switch student persona (recalculates all scores).

2. POST /api/ingest
   - Ingest raw circular text, triggers Groq extraction & relevance scoring.

3. POST /api/parse-file
   - Accepts multipart `File` (PDF/DOCX/TXT), extracts text & auto-ingests.

4. GET/POST /api/emails/scan
   - Scans connected student Gmail inbox via OAuth 2.0 access token for notices.

5. GET/PATCH/DELETE /api/tasks
   - Queries tasks with filters (category, urgency, search), toggles completion or snooze.

6. GET/POST /api/chat
   - Grounded RAG chat endpoint with citation provenance.

7. GET/POST /api/digest
   - Generates an executive AI weekly action briefing of top urgent tasks.

8. POST /api/seed
   - Restores database to clean, highly-diversified campus demonstration state.

9. GET /api/auth/google & GET /api/auth/callback/google
   - Handles Google OAuth 2.0 web consent and secure token exchange.
